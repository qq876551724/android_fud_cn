## 一、 系统概述

**天净加固（TJTools）** 是一套面向 Android 应用（支持原生 Java/Kotlin、UniApp、Flutter 等主流技术栈）的高强度安全防护与免杀加固解决方案，可以完全防报毒，能真正做到Android Fully Undetectable简称Android Fud即完全不可检测。

系统采用 **“Native 底层对抗 + 内存动态加载 + 资源全虚拟化 + 清单文件极净化/结构扰乱”** 的多维立体防御体系，彻底切断 APK 的静态逆向、动态调试及杀软特征扫描路径，并在 Android 12 ~ 14（MIUI / HyperOS、EMUI、ColorOS 等国产深度定制系统）上实现高稳定性与全特性兼容。

## 二、 核心功能与技术特性

### 1. 深度指令加密与多 DEX 动态解密加载
* **DEX 指令全抽离与加密**：加固时将原 APK 的全部业务 DEX 文件进行强混淆与高强度对称加密，打散存入隐匿资产中，外层仅保留极简防护壳。
* **Native 底层加载引擎**：自主研发的 `libtjsec.so` 核心模块在应用冷启动首帧时介入，直接在 Native 内存段完成字节码动态解密与内存加载，彻底规避磁盘落地风险。
* **全系统 Hidden API 豁免穿透**：针对 Android 12+ / 13+ / 14 彻底封锁 Java 反射（报 `access denied`）的问题，在 C++ 运行时直接调用底层 API 豁免接口，完全打破高版本 Android 系统对深层反射的限制。

### 2. AndroidManifest 极净化与四大组件隐匿
* **外层组件全面抹除**：通过 AXML 二进制重构技术，将原清单文件中声明的业务 Activity、Service、Receiver、ContentProvider 从外层清单中彻底剥离，逆向工具反编译后仅能看到一个极简的外层入口。
* **动态组件生命周期接管**：通过壳端核心组件工厂（`CoreComponentFactory`）与代理插桩系统（`StubInstrumentation`），在运行时无感拦截并挂载真实业务组件，完全不影响业务逻辑跳转与主题渲染。
* **通知与前台服务安全兜底**：内置针对 Android 13/14 前台服务通知机制的熔断机制，自动适配通知图标与远程视图（RemoteViews），杜绝因系统 SystemUI 校验缺失而触发的强行终止。

### 3. 全量静态资产与业务资源加密虚拟化
* **业务资源物理剔除**：将原 APK 中的非必要业务布局（`res/layout/`）、业务图片（`res/drawable/`、`res/mipmap/`）、音频及 `assets` 资源彻底从外层 ZIP 中移除，仅保留主桌启动图标与系统配置 xml。
* **资源运行时透明重定向**：将加密后的资产封装为加密资源包，在应用启动及 Service/Activity 运行阶段动态修正 `Resources` 与 `AssetManager`，业务代码通过原有 `R.layout.xxx` 或 `R.drawable.xxx` 仍可透明访问。
* **图片特征清洗与感知哈希破坏**：内置图像重采样与平滑优化器，针对静态超大素材破坏其固有文件 Hash（SHA256）与图像感知哈希（pHash），切断基于视觉特征识别的静态查杀。

### 4. 高危组件脱敏与敏感行为免杀
* **高危无障碍（Accessibility）服务类名脱敏**：加固引擎自动对敏感服务进行动态随机混淆与脱敏。
* **系统设置动态虚拟化 Hook**：壳端底层智能拦截系统无障碍配置查询（`Settings.Secure.getString("enabled_accessibility_services")`），应用内部判断与系统无障碍授权无缝衔接，既消除了杀软误报，又保证了辅助功能在小米/华为等真机上的稳定运行。

### 5. 清单文件 32MB+ 超限膨胀反反编译
* **无损空间膨胀**：基于 Android 原生 C++ `ResXMLTree` 解析机制遇到未知 Chunk 自动按长度指针跳过的底层特性，在 `AndroidManifest.xml` 中无损注入 32MB+ 零填充扩展 Chunk 及多段高熵混淆块。
* **反编译与云沙箱瘫痪**：加固后 APK 压缩包体积仅微增数十 KB，但在反编译或静态扫描解压时单文件瞬间解压至 33MB+，直接触发 Jadx、Apktool、GDA 及各大杀软静态云沙箱的内存溢出（OOM）或 Zip Bomb 防御阈值，使自动化静态扫描分析完全失效。

### 6. ZIP 对齐与多通道规范化签名
* **V1/V2 签名闭环整合**：集成标准的 APK 签名算法体系，兼容 Android 7.0 至 14 的签名校验要求。
* **4 字节对齐（ZipAlign）**：对 SO 库、资源文件进行严格的 4 字节（32-bit）及内存映射对齐，保障应用在真机上快速加载、内存利用率最高。

## 7. 超激进反逆向对抗陷阱
- Win32 保留设备名陷阱：注入 aux.dat、con.dat、prn.dat、nul.dat，使逆向人员在 Windows 下解包（Apktool、WinRAR、7-Zip）时触发系统级拒绝写入错误（ERROR_INVALID_NAME）；
- 畸变诱饵 DEX 陷阱：伪造 DEX 头但注入巨大越界指针，使 JADX、Ghidra 等静态分析工具解析时直接触发 OOM 或异常崩溃；
- 超长文件名与千层塔嵌套：突破 Windows 260 字节 MAX_PATH 限制，使递归遍历反编译器爆栈。
